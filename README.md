# Mediew

具有瀑布流和网格风格的轻量图片/视频浏览器，基于 Electron、sharp 和 ExifTool。

## 功能特性

- **文件夹导航**：左侧树形目录，按需懒加载，避免启动时递归扫描整个磁盘。
- **图片预览**：支持 JPG、PNG、GIF、WebP、TIFF、AVIF。TIFF 由主进程用 sharp 解码后输出缓存 JPEG，不依赖浏览器的原生解码能力。BMP 与 HEIC/HEIF 已从支持列表移除（当前打包的 sharp 无对应解码器，列出只会得到永久破图）。
- **RAW 照片**：支持 DNG、CR2、CR3、CRW、NEF、NRW、ARW、ORF、RW2、RAF、PEF、SRW、MRW、X3F、GPR 等常见相机格式。
- **高性能瀑布流**：首屏只渲染可见批次，进入视口附近后才请求缩略图。
- **缩略图缓存**：普通图片使用 sharp 生成缓存 JPEG，RAW 优先读取内嵌预览。
- **稳定布局**：先探测图片宽高比并预占位，缩略图到达时不会再引起整屏跳动。
- **递归子文件夹**：可在工具栏或设置中开启，显示当前目录及所有子目录中的媒体。
- **目录搜索**：按文件名、相机、镜头、日期或 RAW 格式筛选。
- **收藏筛选**：右键收藏照片，并可只显示收藏内容。
- **拍摄信息**：预览面板显示相机、镜头、光圈、快门、ISO、尺寸和格式。
- **文件操作**：重命名、删除、批量拖拽移动、复制路径、在资源管理器中定位，以及用默认程序打开、移动到指定文件夹。
- **操作反馈**：重命名冲突、目标目录已有同名文件、文件被占用等情况都会明确提示，不再静默失败。
- **键盘操作**：网格与文件夹树都有完整的键盘导航，焦点位置始终可见。
- **视频播放**：进度条、音量、倍速、全屏和画中画等现有功能保持可用。
- **主题与布局**：深色/浅色主题、瀑布流/网格/文件名布局。首次启动为深色主题。
- **无障碍**：全部文字对比度达到 WCAG AA 4.5:1；网格与文件夹树带 listbox/tree 语义与选中状态。

## 更新日志

### 1.1.5

旋转动画方向修复：

- **第四次旋转不再倒转 270°**：旋转角每次都被归一化到 0–359 再写进 `transform`，转到 270° 后再转一次会变成 0°，而 CSS 过渡插值的是旋转矩阵，浏览器按 -270° 的方向转回去，看起来就是"倒着转了一大圈"。现在改为把施加到图层上的角度连续累加（90 → 180 → 270 → 360），反向旋转则从 0 累减为 -90、-180，动画方向始终与按键一致；切换图片或关闭灯箱时重置累加值。

### 1.1.4

灯箱居中修复：

- **打开预览图后图片不再偏到右边**：灯箱图层是 `<img>`，布局盒等于图片原始像素尺寸（常见 6000×4000，远大于容器），原来用 `inset:0` + `margin:auto` 居中，内在尺寸超出包含块时 auto 边距无法变负，浏览器把图片整体推到容器右侧之外，右侧信息栏还会切掉一块。改为 `left/top:50%` + 独立的 `translate:-50% -50%`，按自身尺寸精确回退半个盒子，fit / 原图 / 放大 / 拖拽 / 旋转各状态下视觉中心都严格落在图像区中心。
- **滚轮与 +/- 缩放不再横向漂移**：`zoomTo()` 以视口中心为锚点缩放，却把容器的绝对坐标 `vW/2` 当成锚点传入（正确的锚点应是平移坐标系原点 0），每缩放一次就横向偏移半个图像区宽度。改为按比例缩放 `panX/panY`，缩放中心保持不动。

### 1.1.3

数据安全与稳健性修复（对应 1.1.2 审计的 P0 / P1）：

- **文件名冲突不再被覆盖**：移动、重命名、移动文件夹全部改为「独占创建」语义（同卷硬链接、跨卷 `COPYFILE_EXCL`），目标已存在时明确报错并保留源文件；跨磁盘移动不再因 `EXDEV` 直接失败。
- **选中态与删除**：瀑布流重建/滚到新批次后选中状态不再丢失，删除 N 张只清掉这 N 张的选中；卡片索引同步重建，点击不会再打开错位的那张。
- **不再"照片凭空消失"**：扫描期单个文件 `stat` 失败只跳过该文件；目录读取失败会显示错误空态并可重试，不再伪装成"没有媒体文件"；缓存/收藏 JSON 损坏时备份原文件并从 `.bak` 恢复，绝不拿空数据覆写。
- **格式声明与实际一致**：`.bmp`、`.heic`、`.heif` 从支持列表移除（当前打包的 sharp 无对应解码器），不再出现永久破图。
- **缓存可控**：启动时清理旧版本缓存 JSON、孤儿 `.tmp` 与过期缩略图/预览（默认上限 2 GB，可用 `MEDIEW_CACHE_MAX_MB` 调整）；元数据淘汰改为批量裁剪，5 万条目录不再卡主线程；解码失败进入 5 分钟负缓存。
- **退出不丢数据**：退出前等待在途 EXIF 写入并 flush 存储，3 秒兜底保证窗口一定关得掉；窗口状态保存不再被进程退出打断。
- **交互细节**：灯箱支持窗口缩放重算、加载失败不再永久转圈、补 `role="dialog"` 与 Tab 焦点陷阱；文件夹树快速切换不再被旧请求覆盖；单实例锁 + 启动失败弹错误框而非静默无窗口。
- **无障碍状态同步**：卡片与文件夹的 `aria-selected` 现在跟随真实选中态更新（含 Ctrl 点选、Shift 连选、框选、右键、拖拽与 Ctrl+A），读屏不再读到过期状态。

## RAW 支持说明

Mediew 不修改 RAW 原文件。显示 RAW 时的处理顺序如下：

1. DNG/TIFF-RAW 优先尝试由 sharp 直接解码；
2. 其他 RAW 通过 ExifTool 读取 `PreviewImage`、`JpgFromRaw`、`ThumbnailImage` 或 `OtherImage` 内嵌 JPEG；
3. 如果文件本身没有预览且当前解码器无法读取，界面会明确显示“RAW 预览不可用”。

该策略兼容性广、无需用户安装 LibRaw 或相机厂商软件；但它显示的是 RAW 内嵌预览，不是完整的去马赛克和色彩编辑结果。如果相机文件没有内嵌预览，仍需要后续接入 LibRaw 才能完整解码。

## 缩略图与预览规格

取图规格与单文件版看图工具 gkpv 对齐（见 `services/media-service.js` 顶部常量）。

| 项目 | 规格 | 说明 |
| --- | --- | --- |
| 缩略图最长边 | 640 px | 只限制最长边，短边按比例；源图更小则不放大 |
| 缩略图编码 | JPEG q80、progressive、mozjpeg | 与 gkpv 的 q0.8 一致，mozjpeg 体积更小 |
| 缩略图并发 | 渲染层 8 / 主进程 4 | 渲染层排队并发对齐 gkpv，主进程限流保护 CPU |
| 预览图最长边 | 4096 px | 仅对 TIFF / RAW 生成；其他格式直接加载原图 |
| 预览图编码 | JPEG q92 | 与 gkpv 灯箱重编码质量一致 |
| 宽高比探测 | `sharp().metadata()` 只读文件头 | 结果写入 `dimension-cache.json` 持久化 |

**为什么灯箱对普通图片直接加载原图**：gkpv 的灯箱同样加载原图，这样 100% 缩放才是真正的 1:1 像素。只有浏览器无法解码的格式（TIFF / RAW）才由主进程生成预览。

**与 gkpv 的差异**：gkpv 在渲染进程用 `createImageBitmap` 解码，因此无法处理 TIFF（Chromium 没有 TIFF 解码器，`readImageSize()` 也没有 TIFF 分支，缩略图与灯箱都会失败）。Mediew 把解码放在主进程由 sharp 完成，TIFF / RAW 因此都能正常显示缩略图与预览图，这一点由 `test/image-size.test.js` 与 `test/media-service.test.js` 中的 TIFF 用例锁定。

## 性能设计

- 主进程使用异步 `readdir/stat`，不阻塞 Electron 事件循环。
- 目录快照立即返回，EXIF 与宽高比在后台分批补充，使用缓存和受限并发。
- 元数据缓存位于 `%APPDATA%\mediew\metadata-cache-v2.json`，宽高比缓存位于 `%APPDATA%\mediew\dimension-cache.json`。
- 缩略图规格统一为**最长边 640 px、JPEG q80**（源图更小则不放大），主进程最多 4 路并行生成。
- 预览图规格为**最长边 4096 px、JPEG q92**，只对浏览器无法解码的 TIFF / RAW 生成。
- 缩略图和预览缓存位于 `%APPDATA%\mediew\media-cache`，缓存键包含文件大小与修改时间，文件变化时自动失效。
- 宽高比由 `sharp().metadata()` 只读文件头探测，比完整解码便宜得多；结果持久化后再次进入同一目录无需重新探测。
- 瀑布流按批次创建 DOM，避免一次创建数千张卡片。
- 图片和视频只有接近视口时才加载（预加载边距 900 px），该边距是唯一的加载时机控制；不使用原生 `loading="lazy"`，避免出现「已设置地址但始终不解码」的状态。
- 文件夹树只在展开目录时读取下一级子目录。
- 递归浏览使用异步广度优先遍历，每批并行读取 8 个目录。
- 读取图片后会立即释放文件句柄（关闭 libvips 的文件级缓存），确保用户能正常删除、重命名或移动刚浏览过的文件。

## 安装运行

```powershell
npm install
npm start
```

## 测试

```powershell
npm test
```

真实 RAW 集成测试可通过环境变量启用：

```powershell
$env:MEDIEW_RAW_FIXTURE='D:\samples\photo.CR3'
npm test
```

## 打包

```powershell
$env:ELECTRON_MIRROR='https://npmmirror.com/mirrors/electron/'
$env:ELECTRON_BUILDER_BINARIES_MIRROR='https://npmmirror.com/mirrors/electron-builder-binaries/'
npm run build:zip
```

打包配置会将 `sharp` 原生库和 `exiftool-vendored` 可执行文件解包到 `app.asar.unpacked`，确保安装后的 RAW 功能可用。
